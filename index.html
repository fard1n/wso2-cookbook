WSO2 APIM 4.7 Portals & Security Cookbook

An official, comprehensive manual explaining how to use the WSO2 Web Portals as an application developer and API creator. This guide explains every concept (OAuth2, JWTs, Access Tokens, API Keys, SSL Trust Chains) and walks through every screen, menu option, dropdown, and button with zero guesswork.

UI Focus: Everything here happens in your web browser at https://devportal.parspc.ir/devportal and https://publisher.parspc.ir/publisher.

The Two Portals You Work With

Portal URL Path Primary Persona What It Does
Publisher Portal https://publisher.parspc.ir/publisher API Creator / Backend Dev Creates APIs from Micro Integrator (MI) or developer services (Go), defines resources, sets endpoints, configures policies, and manages lifecycle.
Developer Portal https://devportal.parspc.ir/devportal API Consumer / App Dev Discovers APIs, manages client Applications, subscribes to rate tiers, generates OAuth2/API keys, rotates secrets, and tests endpoints.

Developer Portal Overview & Navigation

🧭 The Consumer Journey

The Developer Portal (`/devportal`) is the storefront of your API ecosystem. It is designed for software engineers building consumer applications (web frontends, mobile apps, daemons, backend integrators).

The 5 Core Steps to Consuming an API Devportal ➔ End-to-End Workflow
Step 1: Explore & Discover

Browse the APIs catalog. Read technical descriptions, review OpenAPI/Swagger schemas, verify rate tiers, and inspect operation schemas.

Step 2: Create an Application

Go to Applications ➔ Add New Application (e.g. LabApp). The Application is your logical client identity container that holds your security credentials and rate quotas.

Step 3: Subscribe to API

Under Subscriptions, bind your Application to the desired API (e.g., CustomerServices 1.0.0) and choose your throttling policy (e.g. Unlimited or 50PerMin).

Step 4: Generate Production / Sandbox Keys

Under Production Keys, generate your OAuth2 Consumer Key & Consumer Secret or click Generate Access Token to obtain a live signed JWT.

Step 5: Test & Integrate

Use the in-browser API Console (Try Out) or run cURL from your terminal with Authorization: Bearer <token> against the Gateway URL https://api.parspc.ir.

1 What is OAuth 2.0? (The Core Principle)

🛡️ Concept Overview: Delegated Authorization

What is OAuth 2.0? It is an open-standard security framework that allows client applications (like your frontend website, mobile app, or cURL script) to access backend API resources without passing permanent passwords over the network on every request.

The Old, Broken Way

Sending permanent usernames and passwords in HTTP headers on every API call. If a hacker intercepts one packet or a server logs the header, your master password is leaked forever.

The OAuth 2.0 Way

You prove your identity to the Key Manager once. It gives you a temporary, signed Bearer Token (ticket) that only works for a short time (e.g. 1 hour) and has limited permissions.

The 4 Actors in WSO2 OAuth2:

OAuth 2.0 Actor WSO2 Component Real-World Role
Client Your Application (e.g. LabApp) The software wanting to call the API (a mobile app, web dashboard, or backend script).
Authorization Server WSO2 Key Manager (Resident / Okta / Keycloak) The security guard that verifies client credentials and issues signed access tokens.
Resource Server WSO2 API Gateway (`api.parspc.ir`) The gateway that checks incoming tokens, validates signatures, and enforces rate limits.
Backend Service Micro Integrator (MI) or Go Microservice The actual database or code that produces business data.

2 Consumer Key vs. Consumer Secret Demystified

🔑 Concept Overview: The Identity Pair

In Developer Portal ➔ Production Keys, WSO2 generates two strings. Many developers confuse them, but they have completely different security roles:

Consumer Key (Public ID)

Equivalent to a Username. It is the unique public identifier of your Application (e.g. IUs4tCrgSTVoLuw5K6pEuu_uiz8a). It is safe to embed in client configurations.

Consumer Secret (Private Password)

Equivalent to a Master Password. It is the private secret (e.g. WntNBAHu6DU9ZlwH8k5SZ6LQQoMa). It must NEVER be exposed publicly or committed to Git. Used strictly to prove to the Key Manager that your app is genuine.

Why did Devportal prompt for the Consumer Secret earlier?
When you clicked "Generate Access Token" or "GET TEST KEY" in Try Out, WSO2 asked: "Enter the consumer secret for the selected application".
Because the Consumer Secret is a master password, WSO2 will not store it in plain text in your browser session for security reasons. You enter the secret, and WSO2 executes the OAuth2 Client Credentials exchange to hand you an access token.

3 Access Tokens & Inside a Live JWT

🎟️ Concept Overview: What is an Access Token?

An Access Token is a temporary digital credential presented in the HTTP Authorization: Bearer <token> header. In WSO2 APIM 4.7, tokens are formatted as JWTs (JSON Web Tokens).

Anatomy of a Real JWT (Dissecting Your Generated Token):

A JWT consists of three parts separated by dots: Header.Payload.Signature

LIVE JWT TOKEN 
eyJ4NXQiOiJZMkUxWXpsaU5UUm1PV....eyJzdWIiOiJkYzNkMjY5Mi1jMWJiLT....mwPaHSMrtzEB5aHRtVeaG9AGjltb3...
JWT Section Decoded Content from Today's Live Token What It Tells the Gateway
1. Header "alg": "RS256"
"kid": "Y2E1YzliNTRmOWI2..._RS256" 		Specifies the cryptographic algorithm (RSA-SHA256) and the Key ID (thumbprint of the public certificate used to verify the signature).
2. Payload (Claims) "iss": "https://publisher.parspc.ir:443/oauth2/token"
"client_id": "IUs4tCrgSTVoLuw5K6pEuu_uiz8a"
"scope": "default"
"exp": 1790714410 (Unix timestamp) 		Issuer: Who created this token (Resident Key Manager).
Client ID: Which Application owns this token (LabApp).
Scope: Allowed permissions.
Expiration: When the token becomes invalid.
3. Signature Cryptographic hash of Header + Payload signed with Key Manager's Private Key. Guarantees that nobody tampered with the payload. If an attacker modifies the expiration time or client ID by 1 bit, the signature fails!
The Big Advantage of JWT: Stateless Verification!
Because all permissions, expiration dates, and signatures are packed inside the token itself, the WSO2 Gateway can validate your token completely in memory (RAM) in 0.1 milliseconds without having to query a database on every API request.

4 OAuth 2.0 vs. API Keys: The Definitive Comparison

⚖️ Concept Overview: Picking the Right Authentication Method

WSO2 APIM 4.7 supports both OAuth 2.0 Tokens and lightweight API Keys. Here is how they compare:

Feature OAuth 2.0 Bearer Token API Key (WSO2 APIM 4.7)
How it is passed Authorization: Bearer <jwt> ApiKey: <key> (or query param)
Lifespan Short-lived (typically 60 minutes) Long-lived (weeks / months / unlimited)
Token Acquisition Requires a 2-step handshake (exchange Key + Secret at /oauth2/token) Generated directly in Devportal; no exchange step needed
Key Rotation Automatic via Refresh Tokens Manual or programmatic, with a 1-hour grace period
Granular Permissions Yes (OAuth Scopes, User context, Roles) Limited (API-specific or Application-bound)
Best Used For User-facing web apps, mobile apps, third-party integrations, high-security APIs Internal microservices, batch daemons, IoT devices, simple scripts

5 The `900900` Error & The SSL Trust Chain Mystery

🔍 The Root Cause Explained: What Went Wrong & How We Fixed It

Earlier today, our first live test failed with 500 {"code":"900900", "message":"Unclassified Authentication Failure"}. Here is the technical breakdown of what happened under the hood:

The Chain of Events:
  1. Your client invoked https://api.parspc.ir/customers/1.0.0/customers with the JWT token.
  2. The APIM Gateway inspected the token's "iss" (Issuer) claim:
    "iss": "https://publisher.parspc.ir:443/oauth2/token"
  3. To verify that the token was legitimately issued by the Resident Key Manager, the Gateway initiated an internal HTTPS call to https://publisher.parspc.ir:443.
  4. publisher.parspc.ir:443 is served by NGINX using the lab self-signed certificate: `parspc-lab.crt`.
  5. Java on the APIM node checked its truststore: client-truststore.jks.
  6. The Crash: parspc-lab.crt was NOT in APIM's truststore! Java aborted the connection with: 
    sun.security.validator.ValidatorException: PKIX path building failed: 
sun.security.provider.certpath.SunCertPathBuilderException: unable to find valid certification path
  7. Because the Gateway could not reach the issuer, it returned 900900 Unclassified Authentication Failure.
The Permanent Fix:
We extracted parspc-lab.crt from NGINX and imported it into /opt/wso2/wso2am-4.7.0/repository/resources/security/client-truststore.jks (alias parspc-lab) on both `wso-apim-1` and `wso-apim-2`.
Immediately, Java trusted the SSL handshake, validated the token, and returned HTTP 200 OK!

Developer Portal: Applications & Team Sharing

📦 Why Applications Exist in WSO2

In WSO2, you do not subscribe to an API as a human user. You subscribe an Application. An Application is a logical security and throttling container representing your client software.

Application Management Controls Devportal ➔ Applications ➔ [Select Application]
Token Type (JWT vs OAuth)

Choose between JWT (self-contained, validated in memory by the Gateway in 0.1ms) and OAuth (opaque reference token requiring back-channel validation). Always default to JWT.

Per-Application Rate Limiting (Token Bucket)

Assign a global quota (e.g. 50 Per Min) to the entire application across all APIs it invokes, preventing runaway client bugs from overwhelming infrastructure.

Team Sharing & Groups

Share an Application with your engineering team or Active Directory / LDAP groups so multiple developers can view keys, rotate secrets, and debug without sharing personal passwords.

Developer Portal: Subscriptions & Tiers

🔗 Binding Applications to APIs

A Subscription is the contractual bridge linking an Application (consumer) to an API (provider). Without a subscription, the Gateway will reject requests with 900908 Resource forbidden even if the OAuth2 token is valid!

Subscription Workflow:
  1. Navigate to your Application (e.g. LabApp) ➔ Subscriptions tab.
  2. Select the API from the dropdown (e.g. CustomerServices 1.0.0).
  3. Select a Business Plan (e.g., Unlimited, Gold - 50req/min).
  4. Click Subscribe. Depending on API settings, the subscription is active immediately or enters a pending approval queue for API administrators.

Developer Portal: The "Generate Access Token" Modal Walkthrough

Pop-Up Dialog Controls Explained

When you click Generate Access Token under LabApp ➔ Production Keys, this dialog handles the OAuth2 Client Credentials exchange:

Consumer Secret Input Box

Paste your application's private master secret (e.g. WntNBAHu6DU9ZlwH8k5SZ6LQQoMa). The `GENERATE` button remains disabled until this is provided.

Scopes Dropdown

Optional filter. If the API creator defined fine-grained permission scopes (like read:customers), you select them here. Leaving it blank requests the default scope (full access to all subscribed operations).

The "GENERATE" Button

Submits the credentials to the Key Manager. The Key Manager verifies the hash, packages the JWT with a 1-hour expiration timestamp, signs it, and returns the Bearer token string to your clipboard.

Developer Portal: API Console (Try Out) & Traps

⚠️ The 3 Most Common Traps in Try Out Console

The Try Out console allows executing live HTTP calls directly inside the browser. Beware of these common traps that cause requests to fail:

Trap 1: The "Failed to fetch" Browser SSL Block

If your lab uses a self-signed SSL certificate, your browser will block background JavaScript fetch() calls with TypeError: Failed to fetch.
Solution: Open a new browser tab, visit https://api.parspc.ir directly, click Advanced ➔ Proceed to site to accept the certificate once, then return to Devportal and click Execute!

Trap 2: Error 900908 (Resource Forbidden)

Occurs when you generated a token for LabApp, but forgot to subscribe LabApp to the specific API. The token is valid, but the subscription check fails.

Trap 3: Expired Bearer Token

Default test tokens expire after 3600 seconds (1 hour). If the console returns 900901 Invalid Credentials, click GET TEST KEY again to refresh.

Publisher: Operations Configuration & The `/*` Wildcard Trap

⚡ Screen Walkthrough: How Resources are Mapped

When you designed the CustomerServices API in Publisher, you encountered the Operations Configuration screen:

Operations Screen Controls Publisher ➔ [Select API] ➔ API Configurations ➔ Resources
Rate Limiting Level (API Level vs Operation Level)

• API Level: All paths share the same quota (e.g., 50 req/min across the entire API).
• Operation Level: Allows assigning different tiers to different methods (e.g. GET /customers allows 100 req/min, but POST /customers only allows 10 req/min to prevent write spamming).

HTTP Verb & URI Pattern Box

Select the HTTP method (GET, POST, PUT, DELETE) and type the path (e.g. /customers).

The Blue "+" Button (Critical Step!)

Typing the path in the box is not enough! You must click the blue `+` button to append the operation to the API definition before clicking Save.

The Default `/*` Wildcard Trap

By default, WSO2 generates catch-all wildcard operations: get /*, put /*, post /*.
Best Practice: Delete the wildcard section using the Trash Can icon! Leaving wildcards makes your Swagger documentation generic and confusing to frontend developers. Defining explicit paths (like GET /customers) produces clean, professional API contracts.

Publisher: Working Copy vs. Revisions (Why Publish was Greyed Out)

🔒 The Immutability Model in WSO2 APIM 4.x

In our session, you noticed the Publish button was greyed out, and the top bar said Revision 1 [Read Only]. Here is how WSO2's revision model works:

The Difference Between Working Copy & Revision:
  • Working Copy (Mutable / Draft): This is your active design canvas. Here, you can edit endpoints, add resources, change security, and transition lifecycles (Publish / Deprecate).
  • Revision (Immutable / Snapshot): When you click "Deploy Revision", WSO2 takes a read-only snapshot (e.g. Revision 1) and deploys it to the Gateway nodes. Because revisions are historical records, the UI locks into `[Read Only]` mode while viewing a revision!
The Solution: Look at the top dropdown menu where it says Revision 1 ▾. Click it and select `Working Copy`. Immediately, edit mode unlocks and the Publish button turns blue!

Publisher: Endpoints Configuration & Base URL Rule

🎯 URL Suffix Arithmetic Explained

When the Gateway forwards a request to the backend service, it automatically calculates the final target URL using Base URL + Resource Path.

Endpoint Arithmetic Example Publisher ➔ API Configurations ➔ Endpoints
Production Endpoint Base URL

http://wso-mi-1:8290/services/phonebook.HTTPEndpoint

Resource Path Defined in Publisher

/phones

Final URL Called by Gateway

http://wso-mi-1:8290/services/phonebook.HTTPEndpoint/phones

The Trailing Slash Warning:
Never put a trailing slash / at the end of your Backend Endpoint URL if your resource path begins with / (e.g. http://backend:5000/ + /customers = http://backend:5000//customers). Double slashes cause many web frameworks to return HTTP 404 Not Found!

Publisher: Lifecycle States & Revisions

🔄 The API Lifecycle Pipeline

APIs in WSO2 APIM move through formal lifecycle stages to protect downstream consumers from unexpected breaking changes.

Lifecycle State Devportal Visibility Gateway Status When to Use
CREATED Invisible Not deployed Initial draft; configuring endpoints and operations.
PROTOTYPED Visible (marked Prototype) Deployed Providing mock data or sandbox endpoints for early consumer testing.
PUBLISHED Fully visible Active on Gateways Live production API available for subscription and token generation.
BLOCKED Visible Rejects traffic (503) Temporary emergency block without deleting subscriptions.
DEPRECATED Visible to existing subs Active Phase-out stage. Existing apps still function, but new subscriptions are blocked.
RETIRED Removed Undeployed Decommissioned; endpoint removed from Gateway.
